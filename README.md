# mobile

Internal backoffice app for iOS and Android, built with Expo (SDK 58, Expo Router, React Native).
It is the mobile side of a project generated by `project-starter`, next to `api/` (Laravel) and
`web/` (Vue). How code is written here — structure, libraries, tests, the native feel — is in
[`AGENTS.md`](AGENTS.md); read it before changing anything.

## Backend

The app talks to the Laravel API of the same project. Start it there with `make up` and seed the
demo accounts, then point the app at it:

```sh
cp .env.example .env.local    # EXPO_PUBLIC_API_URL=http://localhost:8000/api
```

`src/lib/http.ts` is the only module that reads the address; every request goes through it.
`localhost` works on the iOS simulator directly and on the Android emulator through
`adb reverse tcp:8000 tcp:8000`, which `npm run android` sets up.

### On a physical phone

`localhost` on a phone is the phone itself, so the app finds neither the API nor Metro. Put the
Mac's address on the local network into `.env.local` instead, and restart Metro — the value is
inlined when the bundle is built:

```sh
ipconfig getifaddr en0                              # the Mac's LAN address, e.g. 192.168.1.23
EXPO_PUBLIC_API_URL=http://192.168.1.23:8000/api    # in .env.local
```

The phone and the Mac must be on the same Wi-Fi, and the macOS firewall must let incoming
connections reach Docker (port 8000) and Node (Metro, 8081). An Android phone on USB can use
`adb reverse tcp:8000 tcp:8000` and keep `localhost` instead. The address changes with the
network, so check it again when the app suddenly says the server is unreachable.

### Three apps on one phone

One codebase builds three apps that install side by side — **Name (Dev)**, **Name (Test)** and
**Name** — each with its own bundle id, API and Sentry environment. Local work is always the dev
app (`APP_VARIANT=development` in `.env.local`); EAS builds the others:
`npm run build:dev` / `build:preview` / `build:production`. All three run locally with no account;
details in [`docs/builds.md`](docs/builds.md).

### Accounts each project needs

The template is bound to no account. Everything runs locally without them, all three app
variants included. These are set up once per project, under the client's or the company's
organization — never a personal account:

| Account                             | For                                   | Without it                               | Setup                                                      |
| ----------------------------------- | ------------------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| Expo (organization on expo.dev)     | EAS builds, push tokens               | no push, no EAS builds                   | [`docs/builds.md`](docs/builds.md)                         |
| Firebase project (free)             | push on Android                       | Android gets no push                     | [`docs/push-notifications.md`](docs/push-notifications.md) |
| Apple Developer (paid)              | push on iOS, TestFlight, App Store    | iOS gets no push, no distribution        | [`docs/push-notifications.md`](docs/push-notifications.md) |
| Google Play Developer (one-off fee) | Play Store                            | no Play Store release                    | [`docs/builds.md`](docs/builds.md)                         |
| Sentry (free plan: 5k errors/month) | crash and error reports from releases | the app works; nobody sees users' errors | [`docs/sentry.md`](docs/sentry.md)                         |

## Running it

The app uses native code Expo Go does not ship, so it runs in a **development build**:

```sh
npm install
npm run ios        # builds and installs the dev build on the iOS simulator (Xcode 26.4+)
npm run android    # the same on the Android emulator (start it with -no-audio)
npm start          # Metro only, once the dev build is installed
```

After adding a library with native code or changing a config plugin in `app.json`, run
`npx expo prebuild --clean` and build again. Install packages only with `npx expo install`, so
their versions match the SDK.

## What is in it

- **Sign-in** with email and password; the token lives in the secure store, the user only in
  memory and is re-read from `GET /auth/me` on every launch behind the splash screen.
- **Users** — the list (search without diacritics, pull to refresh) and a detail. The reference
  for any screen that reads data.
- **Profile** — own account, profile picture (camera or system photo picker, no media
  permission), editing for admins. The reference for any screen that writes.
- **Notifications** — the phone is registered for the session at sign-in, the system asks for
  permission right after the first sign-in, and the profile shows the state with a test push or a
  way to ask again. Sending needs an Expo, Firebase and Apple account per project:
  [`docs/push-notifications.md`](docs/push-notifications.md).
- Light and dark mode, Figtree, native tabs, sheets, menus and dialogs on both platforms;
  refetch on returning to the app or the network; an error screen instead of a white one.
- **Crash reports** — Sentry, from release builds only: crashes, screens that fail to render,
  5xx answers (with the request id) and responses the schemas reject. Silent until a project
  has its own Sentry account: [`docs/sentry.md`](docs/sentry.md).

## Tests

| Command                                    | What                                           |
| ------------------------------------------ | ---------------------------------------------- |
| `npm test`                                 | Jest — logic, schemas, hooks, screens, routing |
| `npm run lint` / `npx tsc --noEmit`        | ESLint (Expo config) and types                 |
| `maestro --platform ios test .maestro`     | end-to-end flows on the booted iOS simulator   |
| `maestro --platform android test .maestro` | the same flows on the running Android emulator |

Maestro needs the dev build installed, Metro running and the backend up with its demo data.
Every flow must pass on both platforms.
