# external mobile app

The app for a project's **end users** — customers, citizens, members — for iOS and Android, built
with Expo (SDK 58, Expo Router, React Native). In a project generated by `project-starter` it is
`external-mobile-app/`, next to `api/` (Laravel), `web/` (Vue) and, when the project has one,
`internal-mobile-app/` — the staff's app, which this one was forked from and shares its
infrastructure with (variants, OTA, Sentry, push, tests). How code is written here — structure, libraries, tests, the native feel — is in
[`AGENTS.md`](AGENTS.md); read it before changing anything.

## Backend

The app talks to the Laravel API of the same project — its own part of it, `/api/mobile/v1`, with
its own accounts (`mobile_users`), separate from the staff's. Start it there with `make up`, then
point the app at it:

```sh
cp .env.example .env.local    # EXPO_PUBLIC_API_URL=http://localhost:8000/api
```

`src/lib/http.ts` is the only module that reads the address; every request goes through it.
`localhost` works on the iOS simulator directly and on the Android emulator through
`adb reverse tcp:8000 tcp:8000`, which `npm run android` sets up.

### On a physical phone

`localhost` on a phone is the phone itself, so the app finds neither the API nor Metro. Put the
Mac's address on the local network into `.env.local` instead, and restart Metro — the value is
inlined when the bundle is built:

```sh
ipconfig getifaddr en0                              # the Mac's LAN address, e.g. 192.168.1.23
EXPO_PUBLIC_API_URL=http://192.168.1.23:8000/api    # in .env.local
```

The phone and the Mac must be on the same Wi-Fi, and the macOS firewall must let incoming
connections reach Docker (port 8000) and Node (Metro, 8081). An Android phone on USB can use
`adb reverse tcp:8000 tcp:8000` and keep `localhost` instead. The address changes with the
network, so check it again when the app suddenly says the server is unreachable.

### Three apps on one phone

One codebase builds three apps that install side by side — **Name (Dev)**, **Name (Test)** and
**Name** — each with its own bundle id, API and Sentry environment. Local work is always the dev
app (`APP_VARIANT=development` in `.env.local`); EAS builds the others:
`npm run build:dev` / `build:preview` / `build:production`. All three run locally with no account;
details in [`docs/builds.md`](docs/builds.md).

### Accounts each project needs

The template is bound to no account. Everything runs locally without them, all three app
variants included. These are set up once per project, under the client's or the company's
organization — never a personal account:

| Account                             | For                                   | Without it                               | Setup                                                      |
| ----------------------------------- | ------------------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| Expo (organization on expo.dev)     | EAS builds, push tokens, OTA updates  | no push, no EAS builds, no OTA           | [`docs/builds.md`](docs/builds.md)                         |
| Firebase project (free)             | push on Android                       | Android gets no push                     | [`docs/push-notifications.md`](docs/push-notifications.md) |
| Apple Developer (paid)              | push on iOS, TestFlight, App Store    | iOS gets no push, no distribution        | [`docs/push-notifications.md`](docs/push-notifications.md) |
| Google Play Developer (one-off fee) | Play Store                            | no Play Store release                    | [`docs/builds.md`](docs/builds.md)                         |
| Sentry (free plan: 5k errors/month) | crash and error reports from releases | the app works; nobody sees users' errors | [`docs/sentry.md`](docs/sentry.md)                         |
| Google Cloud project (free)         | "Continue with Google"                | the button is hidden; email codes work   | [`docs/sign-in.md`](docs/sign-in.md)                       |
| Apple Developer (paid)              | "Continue with Apple" (iOS)           | the button is hidden                     | [`docs/sign-in.md`](docs/sign-in.md)                       |
| production SMTP                     | sign-in codes to real inboxes         | codes land in the API's log locally      | `api/.env` (`MAIL_*`)                                      |

### Signing in locally

There are no passwords: an address gets a six-digit code by e-mail. Locally the API writes mail to
its log (`api/storage/logs/laravel.log`, or Mailpit if the project set one up), so any address
works — copy the code from there.

For a code that never needs a mailbox (Maestro, store review), the API has **demo accounts**: put
addresses in `MOBILE_DEMO_EMAILS` and a code in `MOBILE_DEMO_CODE` in `api/.env`, then
`make artisan c="mobile:demo-accounts"`. The Maestro flows expect these locally:

```sh
MOBILE_DEMO_EMAILS=maestro@example.com,maestro.code@example.com,maestro.register@example.com,maestro.lang@example.com,maestro.profile@example.com,maestro.theme@example.com,maestro.avatar@example.com,maestro.device@example.com,maestro.prompt@example.com
MOBILE_DEMO_CODE=424242
```

## Running it

The app uses native code Expo Go does not ship, so it runs in a **development build**:

```sh
npm install
npm run ios        # builds and installs the dev build on the iOS simulator (Xcode 26.4+)
npm run android    # the same on the Android emulator (start it with -no-audio)
npm start          # Metro only, once the dev build is installed
```

After adding a library with native code or changing a config plugin in `app.json`, run
`npx expo prebuild --clean` and build again. Install packages only with `npx expo install`, so
their versions match the SDK.

## What is in it

- **Sign-in and registration** by a code mailed to the address (autofill from Mail / Messages,
  "send again" behind a countdown), or with Google and Apple once a project sets them up
  ([`docs/sign-in.md`](docs/sign-in.md)). Registration: username, optional first and last name
  and picture. The token lives in the secure store, the account only in memory and is re-read
  from `GET /mobile/v1/me` on every launch behind the splash screen.
- **Serbian and English** — Serbian by default, switched on the welcome screen or in Settings;
  the server answers, mails and pushes in the same language
  ([`docs/localization.md`](docs/localization.md)).
- **Home** — "Ćao, {name}", pull to refresh, and the place the project's own content goes.
- **Settings** — the account (picture from camera or system photo picker, no media permission;
  username, name and "show my name"), language, theme, notifications, privacy policy
  (`EXPO_PUBLIC_PRIVACY_URL`), app version, sign out, and **deleting the account**, which App
  Store and Google Play require.
- **Notifications** — the phone is registered for the session at sign-in, the system asks for
  permission right after the first sign-in, and Settings show the state with a test push or a
  way to ask again. Sending needs an Expo, Firebase and Apple account per project:
  [`docs/push-notifications.md`](docs/push-notifications.md).
- Light and dark mode, Figtree, native tabs, sheets, menus and dialogs on both platforms;
  refetch on returning to the app or the network; an error screen instead of a white one.
- **Crash reports** — Sentry, from release builds only: crashes, screens that fail to render,
  5xx answers (with the request id) and responses the schemas reject. Silent until a project
  has its own Sentry account: [`docs/sentry.md`](docs/sentry.md).
- **Updates** — over-the-air JS updates per variant (`npm run update:preview` / `update:production`,
  off until the project has an Expo account), and a required-update screen: an app older than the
  API's `MOBILE_EXTERNAL_*_MINIMUM_VERSION` shows only "update required", with a link to the store. Bump
  `version` in `app.json` with every native change: [`docs/updates.md`](docs/updates.md).

## Tests

| Command                                    | What                                           |
| ------------------------------------------ | ---------------------------------------------- |
| `npm test`                                 | Jest — logic, schemas, hooks, screens, routing |
| `npm run lint` / `npx tsc --noEmit`        | ESLint (Expo config) and types                 |
| `maestro --platform ios test .maestro`     | end-to-end flows on the booted iOS simulator   |
| `maestro --platform android test .maestro` | the same flows on the running Android emulator |

Maestro needs the dev build installed, Metro running and the backend up with the demo accounts
above. Every flow must pass on both platforms. The API allows 5 codes an hour per address and 20
per IP: between two full runs clear its limiter with `make artisan c="cache:clear"` in `api/`.
